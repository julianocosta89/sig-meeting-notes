## Key Topics
- Discussion on memory consumption issues in the demo app, particularly related to Java services and feature flags.
- Ongoing efforts to create a lighter version of the demo, including potential removal of certain services and the introduction of an OpenTelemetry Demo Builder (ODB).
- The importance of maintaining vendor agnosticity in the demo while considering user experience and ease of use.
- Proposal to decouple telemetry services from the main Docker Compose setup for better maintainability.
- Introduction of Weaver for schema-driven custom metrics and attributes, with discussions on its implications for documentation and shared schemas.

## Action Items

- Further discussion on the proposal for Docker Compose profiles to manage different service configurations.
- Engage with the community to clarify goals regarding the demo's observability stack and memory consumption.
